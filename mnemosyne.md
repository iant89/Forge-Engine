# Mnemosyne — session memory for Forge-Engine

Long-lived notes for future agent sessions. Anything here was judged worth remembering across

Newest entries go at the bottom with a date. Keep entries short; link to files, don't paste code.

## Repo facts (stable)

- Monorepo: `engine/` (`@forge/engine`, the WebGPU engine), `examples/` (Vite demo scenes),
  `tests/` (vitest, Node + mock GPU), `scripts/`, `tools/`, `benchmarks/`, `docs/`.
- Commands: `npm run typecheck` (engine + examples + tests), `npm run test`,
  `npm run demo` (Vite on 0.0.0.0), `npm run check:wgsl`. Node >= 20.11.
- Session branch convention: work stays on `arena/<id>-forge-engine`; commit + push there, PR from it.
- Vehicle convention everywhere: **+Z is the nose, +Y up, metres**. Wheel names
  `wheel_FL / FR / ML / MR / RL / RR` (−X = left). `VehicleSystem` (order 110) poses the chassis
  entity and each id in `VehicleComponent.wheelEntities` from `vehicle.wheels[]` — same order.
- Mars showcase: `examples/src/scenes/marsShowcaseScene.ts` + `examples/src/assets/glb.ts` (minimal
  GLB loader) + `examples/assets/Perseverance.glb` (checked in, ~8 MB, generated by
  `scripts/convert-perseverance.mjs` from NASA's Draco-compressed source). Converter splits the
  source's single `Wheels_objs` mesh into six hub-centred `wheel_*` nodes via k-means on Z × sign(X).
- Loader contract the converter guarantees: body prims baked to model-root space, `wheel_*` roots
  translate to hub centres with hub-centred children, loader matches `/^wheel_[FMR][LR]$/`.

## 2026-09-24 — invisible rover wheels (only wheel_FL visible)

- **Symptom:** in the Mars showcase only the Left Front wheel rendered; other five missing, no errors.
- **Root cause:** `scripts/convert-perseverance.mjs` packed each wheel prim's vertices per-cluster
  into one array (`globalBase[k]` offsets) but pushed the **global** indices into each per-wheel
  slice, whose vertex array starts at 0. Only `wheel_FL` (base 0) had valid indices; the other 15
  wheel meshes' indices pointed past their own vertices, so the GPU discarded them silently.
  Verified by dumping index min/max vs vert count from the checked-in GLB.
- **Fix (3 parts):**
  1. Converter: rebase with `- globalBase[k]`, throw on a cross-wheel triangle instead of emitting
     garbage, and rank k-means seeds front→rear explicitly (the old `void axleOrder` dead code
     assumed seed order survived convergence).
  2. Repaired `examples/assets/Perseverance.glb` in place (subtract per-mesh index min; all wheel
     ranges were contiguous so this is exact; body meshes were already fine). Fresh-process check:
     all 64 meshes in range. Source `/tmp/Mars2020.glb` was unavailable, hence repair > reconvert.
  3. Guards: `loadGlb` now `console.warn`s on out-of-range indices; `tests/roverGlb.test.ts` asserts
     the six wheel roots + hub positions and in-range indices on every mesh of the checked-in GLB.
- **Lesson:** out-of-bounds index buffers fail silently on the GPU — any future "mesh missing, no
  error" report should dump index ranges first. The debug-bounds overlay (`RoverDebugBounds`) only
  proves the *entity pose*, not that the geometry is drawable.
